# 朝のNASDAQカフェ｜編集記憶

このディレクトリは、OpenClaw型の考え方を朝のNASDAQカフェ向けに限定して実装する長期記憶層です。

目的は、全履歴を毎回読み込むことではありません。今日の主役候補に関係する過去だけを選び、狐が以前の論点、仮説、未解決点、制作上の学びを引き継げる状態を作ります。

## 記憶の層

```text
active_context.md
  現在進行中の重要テーマと直近で見るべき論点

daily/YYYY-MM-DD.md
  最終確定した各回の1〜2行要約、仮説、反対材料、次に見る点

weekly/YYYY-Www.md
  その週に何が変化したか。日次記録の圧縮版

threads/<thread_id>.md
  AI設備投資、HBM、輸出規制、金利など継続テーマ別の履歴

threads/index.json
  話題・企業・用語から読むべきthreadを選ぶ索引

claim_ledger.json
  過去に置いた市場仮説の状態変化と根拠

production-lessons.md
  台本・画面・説明方法について確定した再利用可能な学び
```

## 毎朝読む範囲

原則として次だけを読みます。

1. `active_context.md`
2. 前日の`daily`記録
3. 当週の`weekly`記録
4. 今日の主役候補・企業・用語に一致する`threads`
5. 同じ主張に関係する`claim_ledger`項目
6. 必要な制作上の学び

全日次記録や全過去回を一括投入しません。

## 書き込み条件

記憶はドラフトから作りません。次の内容が確定した後だけ更新します。

- 04審問を反映した最終`episode_package`
- 最終採用経路が確定した`render_spec.json`
- validator通過結果
- 公開記録、または少なくともユーザーが採用したpreview内容

未採用案、審問前の表現、生成に失敗した画像案、却下された因果は恒久記憶へ昇格させません。

## 狐が「覚えている」と言える範囲

狐が覚えるのは、番組内で実際に扱った市場テーマ、確認した事実、当時の仮説、反対材料、次に見るとした指標です。

次のような表現は、対応する記録がある場合だけ使用できます。

- 「前回このテーマを見たときは、回収速度が論点でした」
- 「先週は供給不足を見ていましたが、今回は需要側へ論点が移っています」
- 「僕たちは前回、これをまだ仮説として残しました」

狐の個人的な保有、損益、過去の取引、大学生活上の出来事を記憶として創作してはいけません。

## 記憶と正本の優先順位

記憶は過去の記録であり、現在の事実や01〜04を上書きしません。

```text
現在の一次情報・市場データ
> 01〜04の正本
> 当日の因果調査
> 編集記憶
```

過去の仮説と現在の証拠が衝突した場合は、過去の仮説を維持せず、`claim_ledger.json`で弱化・否定・解決を記録します。
