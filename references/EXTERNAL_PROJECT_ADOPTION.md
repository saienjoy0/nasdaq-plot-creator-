# 外部プロジェクト採用判断｜朝のNASDAQカフェ

## 原則

外部プロジェクトからは、調査の深さ、証拠管理、質問生成、履歴検索、評価方法を積極的に取り入れる。

ただし、次の編集権限は渡さない。

- 主役の最終決定
- 市場因果の最終判断
- Expected / Actual / Gapの確定
- 重要な反対材料の削除判断
- 狐の人物像と語り
- 9シーンの意味
- 売買判断

外部プロジェクトは01〜04を上書きしない。

---

## 1. STORM / Co-STORM

公式リポジトリ：`stanford-oval/storm`

### 公式実装から確認した特徴

- 執筆前にインターネット調査とアウトライン作成を分離する
- 類似テーマから複数の視点を発見し、質問生成を誘導する
- 執筆者と専門家の模擬対話により追質問を作る
- Co-STORMは動的なマインドマップで調査中の概念を整理する
- 公式README自身が、出版可能な完成稿ではなく執筆前工程で特に有用と説明している

### 今すぐ採用

- Perspective-guided question generation
- 新しい証拠からの追質問
- 調査と台本執筆の完全分離
- 先に論点地図を作り、その後でストーリーを圧縮する順序

### 朝のNASDAQカフェ向け変更

Wikipedia記事の視点ではなく、次の視点を使用する。

- 企業公式資料
- 期待値
- 発表・値動きの時系列
- 顧客と需要
- 供給企業とボトルネック
- 競合比較
- 金利・ドル・原油・政策
- 指数・セクターへの波及
- 代替仮説

### 採用しない

- 調査システムが生成した長文記事を、そのまま完成台本にすること
- 一般百科事典型の網羅性を動画の情報量として持ち込むこと
- 外部アウトラインを03の9シーン契約より優先すること

## 2. Open Deep Research

公式リポジトリ：`langchain-ai/open_deep_research`

### 公式実装から確認した特徴

- モデル、検索ツール、MCPを交換可能にする
- 要約、調査、圧縮、最終レポートを別タスクとして扱う
- 過去実装にSupervisor / Researcher型の並列調査がある
- ベンチマークによる評価手順を持つ

### 今すぐ採用

- Supervisorが問いを分割し、専門Researcherへ割り当てる構成
- 公式資料、期待値、時系列、企業関係、マクロ、過去経緯、反証の担当分離
- 調査結果を一度圧縮してから、02へ引き渡す順序
- 検索手段やモデルを契約から分離する設計
- 再現可能な評価用fixtureを持つ考え方

### 朝のNASDAQカフェ向け変更

Researcherは完成文章ではなく、証拠項目と因果エッジを返す。

Supervisorも市場因果を確定せず、`causal_research_dossier`を作って02へ渡す。

### 採用しない

- 一般レポート生成器を編集長として使うこと
- 最終レポートモデルの文章を事実確認なしで公開稿にすること
- 毎朝の調査に不必要な大量トークンを固定投入すること

## 3. Microsoft GraphRAG

公式リポジトリ：`microsoft/graphrag`

### 公式実装から確認した特徴

- 非構造テキストから意味のある構造データを抽出する
- ナレッジグラフ型の記憶により文書群全体の発見を支援する
- 公式READMEはインデックス作成コストが高くなり得ると警告している
- データに合わせたプロンプト調整を推奨している

### 後段で採用

過去の`daily_source_package`、決算資料、episode_packageが蓄積した段階で、次に使用する。

- 企業、製品、顧客、供給企業、政策、技術の関係抽出
- 複数四半期を横断した論点検索
- 同じ市場テーマを扱った過去回の発見
- 関連資料の候補提示

### v0.1では導入しない理由

- 現在は履歴量より、日次調査工程の欠落の方が大きな問題
- 初期段階から高価なインデックス作成を入れる必要がない
- グラフ抽出結果を、市場因果の真実として扱う危険がある

まずMarkdown / JSONの証拠台帳を蓄積し、検索速度と再利用率が問題になった段階で導入する。

## 4. Graphiti

公式リポジトリ：`getzep/graphiti`

### 公式実装から確認した特徴

- 時間とともに変化する事実・関係を扱うTemporal Context Graph
- 各関係に有効期間を持たせる
- 派生した事実を元のepisodeへ追跡できるprovenance
- 新しいデータを増分更新できる
- semantic、keyword、graph traversalを組み合わせた検索

### 後段で積極採用

朝のNASDAQカフェでは、次の問題に合う。

- 会社のガイダンスがいつ変更されたか
- 企業間の顧客・供給関係がいつから確認できるか
- 市場の評価軸がどの決算から変わったか
- 過去の中心仮説が、その後強まったか弱まったか
- 古い関係を現在の事実として誤用しないこと

### 導入条件

- 過去資料が十分蓄積する
- 同じ企業・テーマの履歴検索が毎朝繰り返される
- Markdown検索では時間関係の取り違えが増える
- 運用するグラフDBと更新責任を決められる

v0.1では、Graphitiへ移行できるよう証拠項目に時刻、情報源、独立グループ、限界を保存する。

## 5. DeerFlow

公式リポジトリ：`bytedance/deer-flow`

### 公式実装から確認した特徴

- sub-agent、memory、sandboxを調整するagent harness
- 拡張可能なskillsを中心に構成する
- 設定、doctor、support bundleなど運用診断を重視する
- 2.0は旧Deep Research実装から全面的に書き直されている

### 今すぐ採用

- 調査ロジックを単一の巨大プロンプトにせず`SKILL.md`で分ける
- Specialistごとの責任範囲を固定する
- 設定と市場判断を分離する
- 実行前診断、validator、失敗理由の明示
- 必要資料だけを段階的に読み込む

### 採用しない

- DeerFlow本体を朝の制作基盤へ丸ごと導入すること
- sandboxやsub-agentへ台本の意味を自律判断させること
- 汎用super agentの自由度を、日次本番契約へ持ち込むこと

## 6. 金融マルチエージェントから採用するもの

特定実装を丸ごと導入せず、次の担当分離だけを採用する。

- SEC・IR担当
- 経済指標・政策担当
- 同業比較担当
- 供給網担当
- 市場反応・時系列担当
- リスク・反証担当

### 採用しない

- Buy / Sell / Hold
- 目標株価
- ポートフォリオ配分
- 自律取引
- テクニカル指標だけによる因果説明
- SNSセンチメントだけによる価格原因の断定

## 次に評価する候補

外部プロジェクトは人気や機能数ではなく、次の基準で追加評価する。

1. 見出し以上の発見が増えるか
2. 因果の過剰断定が減るか
3. 過去経緯を正確に再利用できるか
4. 朝の制作時間とコストに見合うか
5. 01〜04の判断を上書きしないか
6. 結果をfixtureとvalidatorで再現確認できるか
